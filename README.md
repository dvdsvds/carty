# carty

리눅스 쉘(fish/zsh/bash 등)과 neovim 컬러스킴/플러그인 설정을 한 곳에 모아,
TUI에서 골라 담기만 하면 자동으로 적용해주는 dotfiles 관리 도구입니다.

쇼핑하듯 카테고리를 돌아다니며 원하는 테마/플러그인을 장바구니에 담고,
마지막에 한 번에 적용합니다.

## 핵심 컨셉

- **장바구니형 UI**: 카테고리(zsh 테마, fish 테마, neovim 컬러스킴 등)를 자유롭게 넘나들며 원하는 항목을 담고, 마지막에 한 번에 적용
- **경량 실행기**: 프로그램 본체는 가볍게 유지하고, 실제 테마/플러그인 데이터는 별도 저장소에서 받아옴
- **안전한 적용**: 기존 설정 파일을 함부로 덮어쓰지 않고, 마커 주석으로 구역을 나누어 삽입 + 최초 1회 백업 보존
- **커뮤니티 확장 가능**: 지원 쉘/도구 목록이 프로그램에 고정돼 있지 않고, 데이터 저장소에 PR로 새 카테고리·항목을 추가할 수 있음

## 설치

```sh
curl -fsSL https://carty.sh/install.sh | sh
```

원라이너 스크립트가 하는 일:

1. OS/아키텍처 감지
2. GitHub Releases에서 맞는 바이너리 다운로드
3. `SHA256SUMS`로 무결성 검증
4. `~/.carty/bin/`에 설치

> **PATH 등록은 자동으로 하지 않습니다.** 설치 스크립트가 사용자의 `.zshrc`/`.bashrc` 같은 쉘 설정 파일을 임의로 건드리지 않기 위한 의도적인 설계입니다. 아래 안내에 따라 직접 등록해주세요.

```sh
# ~/.zshrc 또는 ~/.bashrc 등에 추가
export PATH="$HOME/.carty/bin:$PATH"
```

### 최초 실행 시 주의

최초 실행 시에는 로컬 캐시가 없어 **인터넷 연결이 반드시 필요**합니다. 이후에는 로컬 캐시로 오프라인에서도 브라우징/검색/선택이 가능합니다.

## 사용법

```sh
carty
```

### 기본 조작

| 키 | 동작 |
| --- | --- |
| ↑ / ↓ 또는 `j` / `k` | 목록 이동 |
| → / `l` | 카테고리 진입 |
| ← / `h` | 뒤로 가기 |
| `space` | 체크박스 토글 (리스트 포커스 시) |
| `enter` | 확정 / 다음 단계 |
| `/` | 검색 (어느 화면에서든 호출 가능) |
| `q` | 종료 |

- 검색창에 포커스가 있을 때는 `space`가 원래대로 띄어쓰기로 동작합니다.
- 같은 카테고리 안에서는 항목 하나만 선택할 수 있습니다 (라디오 버튼 방식). 검색 결과에서 선택할 때도 동일하게 적용됩니다. 단, `apply_method`가 `compose`인 카테고리(예: `Zsh Custom`)는 예외로, 완성된 테마 하나를 고르는 대신 여러 항목(경로/git 상태/user@host/프롬프트 문자 등)을 원하는 순서·개수로 자유롭게 담고 항목마다 색을 직접 고를 수 있습니다. 색은 hex를 직접 입력하는 대신 2D 색상 그리드(색조×채도)를 `hjkl`/방향키로 움직여서 고릅니다.
- 장바구니는 화면 한쪽에 항상 표시되며, 담긴 항목을 그 자리에서 확인/제거할 수 있습니다.
- carty는 로그인 쉘 자체(`chsh`, `$SHELL`)는 건드리지 않고, 각 카테고리의 `target_file`에 설정 블록만 써넣습니다. 그래서 기본적으로는 모든 카테고리가 선택 사항이며, 아무것도 담지 않고 적용해도 됩니다. 데이터 저장소에서 특정 카테고리를 `required: true`로 지정하면 그 카테고리에서 최소 1개는 선택해야 적용이 가능해집니다.
- 테마/컬러스킴은 항목 목록에서 바로 설명·색상 미리보기·적용 예시 프롬프트를 확인한 뒤 담을 수 있습니다 (별도 상세 화면으로 들어갈 필요 없음). 각 항목은 이름을 제목으로 하는 카드로 표시되며, 선택 여부는 테두리 색/굵기로 구분됩니다 (커서: 분홍 테두리, 장바구니에 담김: 굵은 분홍 테두리).
- 목록이 한 화면에 다 안 들어가면 커서를 따라 자동으로 스크롤되고, 오른쪽에 스크롤바가 표시됩니다.
- 특정 항목이 다른 항목을 필요로 하는 경우(`depends_on`), 장바구니에 없으면 자동으로 함께 담기고 최종 확인 화면에 "자동으로 함께 추가됨"이라고 표시됩니다.
- 장바구니를 다 채운 뒤 "적용"을 실행하면, 실제로 반영되기 전에 **어떤 파일이 어떻게 바뀌는지 요약하는 확인 화면**이 한 번 더 뜹니다.

### 명령어

| 명령어 | 설명 |
| --- | --- |
| `carty` | TUI 실행 |
| `carty update` | 데이터 저장소의 최신 목록만 확인 (시스템 파일은 건드리지 않음) |
| `carty upgrade` | `update`로 확인된 새 버전 항목들을 실제로 시스템에 반영 |
| `carty uninstall` | carty와 적용된 모든 설정을 제거 (최초 백업 상태로 복구) |
| `carty --version` | 현재 버전 확인 |

> `update`/`upgrade` 구분은 `apt`와 동일한 감각입니다. `update`는 목록만 새로고침하고, `upgrade`는 실제 파일에 반영합니다.

## 동작 원리

### 카테고리와 장바구니

카테고리(zsh 테마, fish 테마, neovim 컬러스킴 등)는 프로그램에 하드코딩돼 있지 않고, 데이터 저장소의 `index.json`에 정의돼 있습니다. 사용자가 항목을 장바구니에 담고 "적용"을 실행하면, carty는:

1. 장바구니에 담긴 항목들의 대상 파일 경로를 확인 (환경변수 감지 포함, 예: `$ZDOTDIR`)
2. alias/함수 이름이 같은 대상 파일 내에서 서로 충돌하지 않는지 검사
3. 카테고리별 고정 우선순위에 따라 구역 적용 순서를 결정
4. 각 대상 파일에 대해 임시 파일에 전체 내용(원본 + 새 구역들)을 새로 작성한 뒤 `rename`으로 원자적 교체

### 적용 방식 (마커 구역)

carty는 사용자의 기존 설정 파일을 통째로 덮어쓰지 않습니다. 대신 마커 주석으로 구역을 나눠 그 안에만 내용을 씁니다.

```sh
# 사용자가 원래 갖고 있던 설정 (건드리지 않음)
export EDITOR=vim

# >>> carty: zsh-theme >>>
# (Nord 테마 설정 내용)
# <<< carty: zsh-theme <<<
```

마커는 `<comment_prefix> >>> carty: <category_id> >>>` / `<comment_prefix> <<< carty: <category_id> <<<` 형태이며, `comment_prefix`는 카테고리마다 다릅니다 (zsh/fish는 `#`, Lua는 `--`).

- 같은 카테고리를 재적용하면 해당 구역만 지우고 다시 씁니다.
- 이번 적용에서 선택하지 않은 카테고리가 있으면, 이전에 적용됐던 구역을 자동으로 삭제합니다.
- 마커가 깨진 것으로 감지되면(사용자가 실수로 마커 일부를 지운 경우 등) 바로 복구하지 않고, 알림을 띄운 뒤 사용자 동의를 받아 백업본으로 복구합니다.

### 백업과 복구

- 각 대상 파일은 **최초로 carty가 손댈 때 딱 한 번만** `~/.carty/backup/`에 백업됩니다. 이후 재적용해도 백업은 갱신되지 않아, 언제나 "carty를 쓰기 전 진짜 원본"이 보존됩니다.
- `carty uninstall`은 이 백업을 이용해 적용 이전 상태로 파일을 되돌립니다.

### 캐시와 업데이트

- 데이터 저장소의 `index.json`과 설정 파일은 `raw.githubusercontent.com`에서 직접 받아오며, 로컬에 캐시됩니다.
- 캐시는 주기적으로 자동 갱신되며, 수동 갱신 단축키도 지원합니다.
- 네트워크가 끊겨도 캐시가 있으면 브라우징/검색/선택은 계속 동작하고, 실제 캐시 갱신·다운로드 시점에서만 실패 알림이 뜹니다.
- carty 바이너리 자체도 같은 주기로 새 버전이 있는지 확인하고, 있으면 자기 자신을 새 바이너리로 덮어써 자동 업데이트합니다. 새 버전은 다음 실행부터 반영됩니다.
- 자동 업데이트로 새 버전이 적용되면 다음 실행 시 TUI 안에서 변경 사항 요약(체인지로그)을 보여줍니다.
- 데이터 저장소에서 이미 적용 중인 항목이 삭제되면, 자동으로 제거하지 않고 "더 이상 지원되지 않음" 경고만 표시합니다. 제거는 사용자가 장바구니에서 빼는 방식으로 직접 실행합니다.

## 디렉토리 구조

### 프로그램 전용 경로 (`~/.carty/`)

```
~/.carty/
├── bin/
│   └── carty              # 바이너리 본체
├── cache/
│   ├── index.json         # 데이터 저장소에서 받아온 최신 메타데이터
│   └── files/              # 캐시된 개별 설정 파일
├── backup/                 # 최초 백업본 (원본 설정 파일)
├── state.json               # 현재 적용된 카테고리별 항목 + 대상 파일 기록
└── log.txt                  # 적용 시도/에러 로그
```

`state.json` 예시:

```json
{
  "zsh-theme": {
    "item": "Nord",
    "item_path": "zsh-theme/nord.zsh",
    "version": "1.0.0",
    "target_file": "/home/user/.zshrc"
  },
  "fish-theme": {
    "item": "Tide (간단 버전)",
    "item_path": "fish-theme/tide.fish",
    "version": "1.0.0",
    "target_file": "/home/user/.config/fish/config.fish"
  }
}
```

`item_path`는 항목의 `file_path`를 그대로 기록한 값으로, `carty upgrade`가 "설치된
버전 vs 최신 버전"을 비교할 때와 항목을 다시 찾아올 때 쓰입니다. `target_file`은
`~`가 이미 홈 디렉터리로 치환된 절대 경로로 저장됩니다.

### 데이터 저장소

carty 프로그램 본체와는 별도의 저장소입니다. 테마/컬러스킴/플러그인 등 실제 설정 데이터가 여기 담깁니다.

```
index.json                  # 전체 메타데이터 (이름, 설명, 카테고리, alias/함수 목록, 미리보기 색상, 버전/해시 등)
files/
  zsh-theme/nord.zsh
  zsh-theme/dracula.zsh
  fish-theme/tide.fish
  themes/nvim/tokyonight.lua
  ...
```

`index.json`은 사람이 직접 관리하지 않고, `files/` 안의 각 파일 상단 YAML frontmatter를 CI(GitHub Actions)가 스캔해서 자동 생성합니다.

## 카테고리 확장 (기여하기)

carty는 지원 쉘/도구 목록을 프로그램에 고정하지 않습니다. 새로운 쉘이나 도구를 지원하고 싶다면 데이터 저장소에 PR을 올려주세요.

### 항목 메타데이터 (YAML frontmatter)

각 설정 파일 상단에 다음과 같은 형식으로 메타데이터를 작성합니다.

```yaml
---
name: Nord
description: 차분한 북극광 색감의 zsh 테마
category: zsh-theme
preview_colors: ["#2e3440", "#3b4252", "#88c0d0"]
provides:
  aliases: []
  functions: []
depends_on: []
---
# 여기부터 실제 설정 내용
```

| 필드 | 설명 |
| --- | --- |
| `name` | 화면에 표시되는 항목 이름 |
| `description` | 짧은 설명 |
| `category` | 소속 카테고리 경로 |
| `preview_colors` | TUI 항목 목록에서 보여줄 색상 미리보기 (hex 배열, 최대 3개) |
| `provides.aliases` / `provides.functions` | 이 항목이 정의하는 alias/함수 이름 목록 (충돌 검사에 사용) |
| `depends_on` | 이 항목이 필요로 하는 다른 항목들의 `file_path` 목록 (항목에는 별도 id가 없고 `file_path`가 곧 고유 식별자입니다) |

### 카테고리 메타데이터

새 카테고리(예: 새로운 쉘) 자체를 추가하려면 카테고리 정의를 추가합니다. 아래는 실제로 반영된 `fish-theme` 카테고리 예시입니다.

```json
{
  "id": "fish-theme",
  "label": "Fish Theme",
  "required": false,
  "priority": 2,
  "apply_method": "marker_section",
  "target_file": "~/.config/fish/config.fish",
  "comment_prefix": "#"
}
```

| 필드 | 설명 |
| --- | --- |
| `id` | 카테고리 고유 식별자 (변경 금지) |
| `label` | 화면 표시 이름 |
| `required` | 이 카테고리에서 최소 1개 선택이 필수인지 여부 |
| `priority` | 파일 내 구역 적용 순서 (숫자가 작을수록 먼저 적용) |
| `apply_method` | 적용 방식. `marker_section`(카테고리에서 항목 하나를 라디오로 골라 그대로 적용) 또는 `compose`(여러 항목을 자유 순서·개수로 담고 항목마다 색을 골라 하나로 합쳐서 적용, 예: `zsh-custom`) (추후 `multi_file`, `command`, `symlink` 확장 예정) |
| `target_file_env` | 대상 파일 경로를 담은 환경변수 이름 (설정돼 있으면 우선 사용, 예: `ZDOTDIR`) |
| `target_file` | `target_file_env`가 없거나 비어 있을 때 쓰는 기본 경로 (`~`는 홈 디렉터리로 치환) |
| `comment_prefix` | 마커 주석에 쓸 주석 기호 (zsh/fish/bash는 `#`, Lua는 `--`) |

CI는 `depends_on`에 순환 의존(A→B→A)이 있으면 `index.json` 생성 단계에서 빌드를 실패시켜, 잘못된 데이터가 저장소에 반영되지 않도록 사전 차단합니다.

### PR과 리뷰

새 항목/카테고리는 Fork → 수정 → PR로 자유롭게 제안할 수 있지만, 실제 저장소 반영(Merge)은 메인테이너가 직접 diff를 검토한 뒤에만 진행됩니다. 자동 병합은 지원하지 않습니다 (`apply_method: command` 등으로 임의 명령 실행이 가능해질 수 있어, 사전 리뷰를 원칙으로 합니다).

```sh
carty uninstall
```

- 적용됐던 설정 파일(`.zshrc` 등)도 최초 백업 상태로 복구합니다.

## 문제 해결

- **쓰기 권한 에러**: 대상 파일에 쓰기 권한이 없으면 어떤 파일인지 에러 메시지로 알려줍니다. sudo를 자동으로 요청하지 않으니, 직접 권한 문제를 해결한 뒤 재시도 키를 눌러주세요.
- **버그 제보**: `~/.carty/log.txt`에 적용 시도/에러 내역이 기록됩니다. 이슈를 등록할 때 이 파일을 함께 첨부해주세요.
- **색상이 깨져 보임**: 사용 중인 터미널이 트루컬러(24bit RGB)를 지원하지 않을 수 있습니다. carty는 자동으로 색을 낮춰 표시하지 않고 안내 메시지만 띄우니, Windows Terminal, iTerm2 등 트루컬러 지원 터미널 사용을 권장합니다.
- **이미 실행 중이라는 메시지**: carty는 동시 실행을 막기 위해 락 파일을 사용합니다. 다른 터미널에서 이미 carty가 실행 중인지 확인해주세요.

## 지원 범위

- **OS**: 리눅스 전용입니다. macOS는 지원하지 않습니다 (zsh/neovim 생태계를 공유하지만 메인테이너가 직접 검증할 수 없는 플랫폼이라 제외했습니다).
- **현재 카테고리**: zsh 테마, fish 테마, neovim 컬러스킴. bash 등 다른 쉘은 아직 없습니다.
- 쉘/도구 자체는 커뮤니티 PR로 계속 확장됩니다. 지원 현황은 데이터 저장소의 `index.json`을 참고해주세요.

## 보안

- 설치 스크립트로 받은 바이너리는 GitHub Actions가 릴리즈 빌드 시 생성한 `SHA256SUMS`로 무결성을 검증합니다.
- 데이터 저장소에 반영되는 모든 PR은 메인테이너의 직접 리뷰를 거칩니다.
- carty는 sudo 권한을 요구하지 않습니다. 개인 설정 파일에 sudo가 필요한 상황은 비정상적인 것으로 간주합니다.
